## Q1 — build-with-cxx: **VERDICT = build WITH C++ (do NOT --disable-build-with-cxx).**

gcc-4.8+ removed the C-only build path; gcc-10 is implemented in C++ and its host source is `.cc`.  R9
used `--disable-build-with-cxx` only because ITS host (gcc-4.0.4) is C-only and gcc-4.7's own source is
still C-compilable.  For R11 a real C++ host now exists (R9's g++), so:

- **CC** = `gcc-cc` wrapper over R9's `gcc` (C).
- **CXX** = `gcc-cxx` wrapper over R9's `g++` (C++) — links R9's `libstdc++.a`.
- **No** `--disable-build-with-cxx` (the option is obsolete/ignored on gcc-10 anyway).

**R9's libstdc++ availability — CONFIRMED.**  R9's `build.ncl` captures `cxx_libs = usr/lib/*.a`
(libstdc++.a + libsupc++.a) and `cxx_includes = usr/include/c++/**`.  In R11's sandbox those land at
`/usr/lib/libstdc++.a` and `/usr/include/c++/4.7.4/…`.  The build.sh adds a **fail-loud infra check** for
`/usr/lib/libstdc++.a` and probes `/usr/include/c++/*/x86_64-linux-gnu/bits/c++config.h` (version-agnostic,
so a 4.8.5/9.5.0 intermediate swap still resolves cleanly).

## Q2 — gcc-cc / gcc-cxx wrappers for R11

Both wrappers point at **R9's** gcc/g++ (`command -v gcc`/`g++`), forced onto R7's `/usr/lib/musl-bedrock-
1.2.5` sysroot (their own baked search points at the coin-flip `/usr`).  `-nostdinc` drops `/usr` C headers;
`-B/-L $SR/lib -static` gives the static musl link.

**The gcc-cxx wrapper is the subtle one — findings wall #5 is SOLVED here, not merely "watched".**  The
draft's naive posture ("-nostdinc only, keep g++'s built-in C++ dirs, inject musl via -isystem") has an
`#include_next` ordering hazard:

- libstdc++'s `<cstdlib>` ends with `#include_next <stdlib.h>` — it must reach **musl's** stdlib.h.
- GCC doc: `-isystem dir` is searched *"after -I but **before** the standard system directories."*  The
  C++ std header dirs ARE standard system dirs → the injected `-isystem $SR/include` sorts **before** them.
- Result: `<cstdlib>` is found *after* musl in the search order, so its `include_next` steps **over** musl
  → `stdlib.h: No such file` (or, worse, silently reaches glibc `/usr/include`).

**Fix (identical to R9's own smoke-gate posture):** `-nostdinc -nostdinc++` to drop BOTH built-in chains,
then re-add EXPLICITLY in order: **C++ std hdrs (R9's) → gcc freestanding → musl C hdrs.**  Now `<cstdlib>`
is found in `CXX_BASE_DIR` and its `include_next <stdlib.h>` lands on `$SR/include`.  The wrapper discovers
`CXX_BASE_DIR`/`CXX_TGT_DIR` from the `c++config.h` probe (no hard-coded builder version).  This ordering
also protects the **host** compile of gcc-10's own C++ TUs, not just the smoke gate.

## Q3 — libstdc++ musl support: which R9 fixes transfer / drop / are new

| R9 fix | R11 verdict | why |
|---|---|---|
| (a) `--disable-build-with-cxx` | **DROP** | obsolete (gcc-4.8+); R11 builds WITH C++ (Q1). |
| (b) gcc-cc wrapper (musl sysroot, -static) | **TRANSFER** | retargeted to R9's gcc; same -B/-L/-isystem posture. |
| (c) `CFLAGS_FOR_TARGET/CXXFLAGS_FOR_TARGET="-B -L $SR/lib -static"` | **TRANSFER (load-bearing)** | libstdc++ configure LINK test needs `-static` + musl crt or it trips `GCC_NO_EXECUTABLES` ("Link tests are not allowed").  **The draft dropped this — RESTORED.** |
| (d) `sed os/gnu-linux→os/generic` (libstdc++ ctype) | **TRANSFER (load-bearing)** | we use the **-gnu** triplet on musl; libstdc++ `configure.host` maps `-gnu`/`linux*` → `os/gnu-linux`, whose `ctype_base.h` uses glibc `_ISupper/_ISalpha/…` that musl lacks.  gcc-10's musl awareness keys on a `*-linux-MUSL` triplet — which we deliberately don't use — so it does NOT rescue us.  **The draft dropped this — RESTORED.** |
| (e-1) `--disable-libmudflap` | **DROP (obsolete)** | libmudflap was removed in gcc-4.9; not passed. |
| (e-2) `--disable-libitm` | **NEW (add)** | libitm still exists in gcc-10 + is musl-risky; unneeded → disable. |
| (f) fixincludes no-op stub + `STMP_FIXINC=` | **TRANSFER** | permanent gcc-rung pattern (musl headers are clean). |
| unwind `struct siginfo/ucontext` sed | **NO-OP guard** | fixed upstream in gcc-8; `[ -f ] && sed` won't match.  Kept for provenance symmetry only. |
| (g) C++ smoke gate | **TRANSFER + upgraded** | now C++14 (vector+lambda+accumulate) proving static libstdc++; **fixed** to use the NEW g++'s own `-print-file-name=include` (draft used R9's `$GI` — a bug) and the `-nostdinc -nostdinc++` explicit-dirs posture. |

Net-new vs R9 (beyond the wrapper/flags): `--disable-libstdcxx-pch` (OOM-pole reducer; skips the big
precompiled-header build, functionally inert), `.tar.xz` (xz in the closure), and the libstdc++ output
captures (`usr/lib/*.a` + `usr/include/c++/**`) already present in the draft build.ncl.

## Q4 — ISL / LTO / fixincludes / smoke gate

- **`--without-isl`**: kept.  ISL is Graphite-only + orthogonal to LTO; gcc-10 builds without it.  **Never
  place ISL in the closure** (permanent bedrock stance — bedrock does no `-fgraphite`).  No ISL rung.
- **`--disable-lto`**: kept.  The lto-plugin is a `.so` (can't link static musl); LTO is not needed to
  bootstrap.  Orthogonal to ISL.
- **fixincludes**: no-op `fixinc.sh` stub in both the source and build `fixincludes/` dirs + `STMP_FIXINC=`
  on both make lines.  musl headers need no fixing.
- **smoke gate**: C++14, fail-shut; asserts the built g++ links its OWN static libstdc++.a against musl.

## Configure line (final)

--enable-languages=c,c++

## PREDICTED WALLS (ranked)

1. 🔴 **C++11-capability gap in the host g++ (the pivot's core risk).**  gcc-10.4 is documented
   C++98-bootstrappable, so in principle R9 gcc-4.7.4 (full C++98) builds it.  BUT `--disable-bootstrap`
   means R9's g++ compiles **every** gcc-10 `.cc` directly, and 4.7.4's *partial* C++11 could still bite a
   specific TU if gcc-10's build opportunistically enables `-std=gnu++11` and uses a 4.7-incomplete feature
   (inheriting ctors / ref-qualifiers / `<type_traits>` gaps).  **Contingency:** insert R9.5 = gcc-4.8.5
   (or 9.5.0) as an intermediate builder — the build.ncl CC import is the single one-line swap-point.
   *This is the one wall no amount of build.sh tuning fixes; it's a compiler-capability question the first
   cloud build answers definitively.*

2. 🟠 **libstdc++ target-lib link → `GCC_NO_EXECUTABLES` ("Link tests are not allowed").**  The fresh xgcc
   must link a static-musl executable during libstdc++ configure.  Guarded by the RESTORED
   `CFLAGS_FOR_TARGET/CXXFLAGS_FOR_TARGET="-B -L $SR/lib -static"` (R9 fix (c)).  If it still trips, the
   miss is a startfile/crt path (`crt1.o`/`crti.o`/`crtn.o` not found under `$SR/lib`) or a `-static`
   that a libstdc++ sub-configure drops — check `libstdc++-v3/config.log` for the failing link.

3. 🟡 **libstdc++ ctype build against musl (the os/generic sed).**  If the RESTORED
   `os/gnu-linux→os/generic` sed is somehow insufficient on gcc-10 (e.g. a different glibc-ism in
   `os/generic/os_defines.h`, or a `_GLIBCXX_USE_*` configure probe that misfires on musl), it surfaces as
   a named compile error in `libstdc++-v3/` (`_ISupper undeclared`, or a missing `secure_getenv`/
   `__cxa_thread_atexit_impl` probe).  Fix = one targeted sed at the named symbol.  *Contingency escalation:*
   configure the honest `x86_64-linux-musl` triplet (auto-selects os/generic + musl specs) — bigger change,
   ripples into downstream multiarch dir names; hold as a last resort.

Lower / well-understood:
4. 🟡 **CXX-wrapper include order** — addressed by the `-nostdinc -nostdinc++ + explicit dirs` posture, but
   the first cloud build is the arbiter that `<cstdlib>→<stdlib.h>` resolves to musl (a wrong `CXX_TGT_DIR`
   probe would surface as `bits/c++config.h: No such file`).
5. 🟡 **Model-B completeness on the larger gcc-10 generated set** — a LOUD regen stub may fire and name a
   file (likely `gengtype-lex.cc` — already added to the touch-list); broaden per the named miss.  Run a
   local configure-probe of the extracted tree first.
6. 🟠 **Sequencing: R10 (binutils-2.41) is drafted but not sealed as R11's assembler.**  build.ncl uses R5
   binutils-2.30 as a stand-in (handles x86_64 output fine; gcc-10 default emits no CET/endbr64 without
   `--enable-cet`).  Swap the import to `../stage0-binutils-2.41` once R10 seals.
7. 🟢 **OOM / wall-time** — gcc-10 `cc1plus` + libstdc++ are bigger than R9.  `-j1`, `--disable-libstdcxx-
   pch`, 16G builder, warm RemoteCache (whole R5–R9 closure HIT), queue LAST/serial.

## Observations (beyond scope)
- **The as-delivered draft build.sh would very likely FAIL its first cloud build for a non-pivot reason.**
  It dropped R9's two load-bearing fixes — `CFLAGS_FOR_TARGET…-static` (→ `GCC_NO_EXECUTABLES` at libstdc++
  configure) and the `os/generic` ctype sed (→ `_ISupper undeclared` in libstdc++) — and its smoke gate
  used R9's `$GI` instead of the new g++'s own include dir.  Those masked the true pivot verdict (wall #1)
  behind two avoidable plumbing failures.  The corrected build.sh restores all three.  *Lesson mirrors
  MEMORY's "compiles ≠ correct" and "verify load-bearing claims": the 10.5 findings' Q4 reasoned from
  Alpine building libstdc++ "unpatched", but Alpine uses the -musl triplet that auto-selects os/generic —
  the -gnu-on-musl posture we inherit from R6→R9 does not get that for free.*
- **The 10.5 findings doc's Observation "R9 may be dropping libstdc++.a" is now RESOLVED**: R9's build.ncl
  DOES capture `cxx_libs`/`cxx_includes` (the workflow caught it 2026-07-01, per the R9 build.ncl comment).
  R11's infra check makes that dependency explicit and fail-loud.
- **Recommend recording "os/generic is mandatory whenever we build libstdc++ on a -gnu triplet over musl"**
  as a bedrock reflex — it will recur on every future gcc rung (B4+ glibc-based rebuilds excepted) unless
  we switch to the honest `*-linux-musl` triplet, which is the cleaner long-term fix worth its own decision.
